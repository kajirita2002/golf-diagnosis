# 設計：Golf Swing Diagnosis Engine

「動画に骨格を描くアプリ」ではなく、**「原因の仮説を立て、実験して、効いたものだけを残す」アプリ**。
当てるだけのアプリは誤診が見えない。実験するアプリは誤診が次のセッションで見え、それが学習データになる。

## 1. 因果の階層（診断の背骨）

```
L0 球筋        曲がり・打ち出し・スピン軸         … 結果
   ↑ 物理（D-plane・ギア効果）でほぼ決まる      ← physics パッケージ（Go・式）
L1 インパクト   フェース・パス・入射角・打点・最下点  … TrackMan が実測
   ↑ ここから先は相関                           ← 分析サービス（Python・統計）
L2 クラブの動き  シャフトの面・手元・ヘッドの軌道    … 動画（Phase 1〜）
L3 身体の動き   骨盤・胸・前傾の起き上がり・頭       … 動画（Phase 1〜）
```

- 上の層から順に降りる。**下の層は、上の層を説明できる範囲でしか探さない。**
- L2・L3 の目的変数は球筋ではなく **L1**（例：フェース・トゥ・パスのばらつき）。
- 身体の特徴量を当てずっぽうに全部比べない（多重比較で必ず何かに差が出る）。

## 2. 判定を確率のふりにしない

「Confidence 84%」は較正されていないので出さない。代わりに出すもの：

- 証拠の件数（「6球中6球」）・効果量と 95% 区間・反証
- 4段階＋α：`strong` / `moderate` / `weak` / `none` / `worse`、足りなければ **`insufficient`**
- 何も言わないことも正しい出力の1つ（`MIN_BLOCK_N` = 5）

## 3. 実験のループ（このアプリの中心）

```
仮説 → 介入（ドリル・意識する1点） → ブロック実験 → L1 が動いたか → 仮説を更新
```

- 1セッションの中で `baseline`（基準）→ `intervention`（介入）→ `retention`（意識を外して定着を見る）。
- 判定は「改善量の 95% 区間が 0 より上」かつ「改善量が MMD（意味のある最小の差）以上」。
- この記録が、あとで Personal Model を作るためのラベル付きデータになる。

## 4. 計測の約束

- 保存は **SI 単位・右打ちの座標**。左打ちは取り込みで左右の角度を反転する（打点のトゥ／ヒールは反転しない）。
- 計算で埋めた項目は `derived`、手で入れた項目は `manual`、計測器の推定値は `estimated` に記録する。
- 取り込んだ CSV の行は `raw` にそのまま残す（あとで読み直せるように）。
- 診断には必ず版を付ける（`physics/0.1`・`analysis/0.1`）。閾値を較正したら版を上げる。
- **打点が無いと、スライスの原因をフェースと取り違える。** 打点が無い曲がりには入力を促す。

## 5. 2段の速さ

| 段 | どこ | 速さ | 中身 |
|---|---|---|---|
| 速い診断 | Go の API | 1球ごと・数ミリ秒 | L0→L1 の物理分解 |
| 深い診断 | Python の分析サービス | セッション単位 | Good 判定・原因の群・ばらつきの要因・実験の評価 |

分析サービスが落ちていても、1球ごとの分解は返る（テストで固定）。

## 6. 段階ごとの計画

| Phase | 作るもの | 次に進む条件 |
|---|---|---|
| **0（いまここ）** | TrackMan CSV だけ。物理分解・自動 Good 判定・ばらつき・ブロック実験 | 実験で L1 が動いたケースが記録できる。翌週も使う |
| 1 | 後方（DTL）1台・240fps・ArUco マーカー。2D 特徴量5〜8個。再測定の一致度を測る | 採用した特徴量すべてで「ショット間の差 ＞ 測定誤差」 |
| 2 | 正面（Face-on）追加・2台のペア同期・TrackMan との自動紐付け・コーチの画面 | コーチの採用率・診断→実験で改善した割合が測れる |
| 3 | 3D・クラブフェースの推定・Personal Model | ラベル付きの実験が十分に溜まる |

## 7. Phase 1 以降の要点（レビューで決めたこと）

- 撮影は **240fps・高速シャッター**。60fps だとダウンスイングが15フレームしかない。
- 同期は音だけに頼らない（音速で数ms〜十数msずれる・隣の打席の音）。最終合わせは画像、時刻は **PTS**。
- **1球ごとのクリップではなく、セッションを連続で撮って自動で切り出す。** TrackMan の時刻と打った間隔の並びで突き合わせる。
- カメラの位置の揃え方が、モデルの精度より効く。**ArUco のボードをボールの横に置く。**
- 撮影アプリは iOS ネイティブ（240fps・2台同期・PTS）。
- 特徴量ごとに「測定誤差の予算」を作り、満たさないものは診断に使わない。
- LLM は構造化 JSON を文章にするだけ。**出力の数値は入力と突き合わせて検証する。** ドリルはコーチが作った集から選ぶ。

## 8. 実データで分かったこと（2026-09-17・57球。`testdata/real/`）

- **D-plane の予測は実測に合う。** アイアンとユーティリティで、予測したスピン軸と実測の差の中央値は 1° 以内。
- **Imp. Offset はマイナスがヒール。** 5番ウッドで、打点のずれと予測からのずれの向きが全部ギア効果と一致した。
- **スピンロフト 8° 未満（トップ・薄い当たり）では予測しない。** 分母が 0 に近づいて −62° のような値が出た。
- **ヒール 30mm を超える当たりは別の問題として出す。** TrackMan がクラブの値を取れないことが多く、
  フェースとパスが無くても原因は打点と言える。アイアンで一番大きなミス（右へ 38〜42m）は全部ここだった。
- **ミスヒットは除外の候補として出し、人が決める。** ただしばらつきの要因分析からは外して計算する（トップ1球で回帰が壊れた）。
- **1本あたりの球は少ない。** 同じ種類のクラブをまとめて見る（左右はキャリーに対する割合）。
- 取り込みは TrackMan の画面の表（省略した列名・R/L 付き・「-」・Average / Consistency の行・クラブの列なし）に合わせた。
